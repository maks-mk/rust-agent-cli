# Потоковый Shell

Реализация задания `tz_shell.md`, 5 ноября 2026 года.

## Устройство

`shell_output_streaming` сохраняет прежний запуск группы процессов, таймаут и
остановку потомков. `shell_stream::drain` читает stdout и stderr через независимые
ветви `tokio::select!`, блоками до 8192 байт. Ожидание завершения процесса идёт
параллельно с чтением. Дополнительных задач на фрагменты вывода нет.
Обычный ASCII-текст добавляется целыми фрагментами. После каждых 64 KiB чтения
задача уступает управление runtime: непрерывно готовые трубы не задерживают UI
до исчерпания стандартного бюджета операций Tokio.

У каждого вызова собственные декодеры UTF-8/ANSI, курсоры stdout/stderr и кольцо
из пяти строк. Строка ограничена 2048 байтами, включая отметку сокращения;
при вытеснении строки её выделенная память используется повторно. Продолжение
вытесненной незавершённой строки пропускается до следующего перевода строки;
обновление через `\r` может снова показать её актуальное состояние.

В обычную очередь событий отправляется один `ShellStream` с `watch::Receiver`.
Дальнейшие снимки заменяют предыдущее значение в канале с интервалом 34 мс.
Отстающий UI получает только последний снимок. Он обновляет соответствующую
карточку и её кэш; частота отрисовки по-прежнему ограничена интервалом 34 мс.
Блокировки канала не удерживаются во время чтения процесса или ожиданий.

Захват для модели независим: по 20 000 байт начала и 10 000 байт конца каждого
потока, всего до 60 000 байт исходного вывода плюс служебные отметки пропусков.
Пять строк интерфейса не влияют на этот результат или историю сообщений модели.

Активная карточка занимает две строки заголовка/команды и до пяти строк вывода.
Переносов команды и строк вывода нет; обрезание учитывает ширину символов.
Завершённая карточка занимает две строки. Итоговый снимок сохраняется в истории
инструмента, а канал удаляется. При отмене отображается `cancelled`.
Полный исполняемый скрипт и диалог подтверждения не сокращаются.

ANSI-последовательности удаляются, а не эмулируются как полноценный терминал.
Буферизацию внутри дочерней программы этот механизм не меняет.

## Проверки

```powershell
cargo test -- --test-threads=4
cargo clippy --all-targets -- -D warnings
cargo fmt --check
cargo test --release --lib shell_stream_stress -- --ignored --nocapture
cargo test --bin rust-agent ui::inline_tests::four_shell_streams_keep_bounded_cards_and_cached_history -- --nocapture
```

Проверяются разбиения Unicode и ANSI на границах байтов, CR/CRLF, отсутствие
перевода строки, пустой вывод, обе трубы, ограничение памяти и медленный UI,
независимые команды, отмена, ошибка запуска, ненулевой код, остановка потомков
по таймауту, сохранение полного захваченного результата и восстановление сессии.
Рендер проверяется через Ratatui `TestBackend`, в том числе при изменении ширины.

Нагрузочный тест запускает четыре реальных процесса, каждый пишет в обе трубы.
Используется многопоточный Tokio runtime с четырьмя worker-потоками, как в
приложении (в приложении количество worker-потоков определяется Tokio).
В Windows суммарно проходит 66 060 288 байт (63 MiB). Параллельно опрашиваются
каналы с интервалом 34 мс; проверяются изоляция вывода, размер снимков и пределы
захвата для модели. Отдельный тест обновляет четыре карточки сто раз поверх
тысячи сохранённых записей: форматируются только четыре активных карточки,
рост высоты ограничен двадцатью строками вывода.

Документация Tokio и Ratatui 0.29 проверена через Context7.

## Результаты на Windows

- Полный прогон: 154 теста библиотеки и 315 тестов приложения прошли; 9 проверок
  в этих двух наборах пропущены как явно запускаемые профили/интеграции.
  Нагрузочный тест выполнен отдельно. `clippy --all-targets -D warnings`,
  `cargo fmt --check` и `git diff --check` проходят.
- Release, четыре команды, 63 MiB: 2,106 с, 29,9 MiB/с. Максимальный интервал
  опроса после появления вывода всех четырёх команд — 47,66 мс. Интервал с учётом
  запуска PowerShell — 162,69 мс; это отдельная метрика, не задержка рендера.
- Повтор с опросом памяти процесса: 2,795 с, 22,5 MiB/с, 0,859 с CPU;
  максимальный интервал во время потока — 63,27 мс. Выборочный максимум RSS —
  6 754 304 байта, private memory — 3 006 464 байта. Это память тестового Rust
  процесса без дочерних PowerShell, измеренная каждые 50 мс. Параллельно в этом
  повторе работал `clippy`, поэтому цифры не являются гарантией задержки.
- При той же нагрузке в однопоточном тесте обработка ASCII фрагментами снизила
  CPU с 2,578 до 0,594 с относительно первоначальной побайтовой реализации.
  Передача управления после 64 KiB дополнительно ограничивает непрерывную работу
  одного читателя; частота публикации снимков остаётся ограниченной интервалом 34 мс.

Ограничения размеров проверяются отдельно от замеров времени: длинные строки
без `\n`, большой объём данных, накопление вывода при не читающем UI и закрытие
каналов после завершения/отмены покрыты автоматическими тестами.
